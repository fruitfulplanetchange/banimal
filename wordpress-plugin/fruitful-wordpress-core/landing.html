What it does

One job, shared by every brand.

Every Fruitful brand connector plugin needs the same three things. This plugin is where they live once, not once per plugin.

shared plumbing
01

API client, cache, REST bridge

One outbound HTTP client, one transient cache, one narrow REST bridge — every brand connector authenticates, times out, and stays inside the same permission boundary the same way.

  • Bearer-token auth, timeout, and error handling in one place
  • Every response cached — a public page load never calls the Fruitful API directly
  • Two narrow, edit_pages-gated routes: /brands, /brand/{id} — never a generic proxy
elementor
02

One widget, safe on its own

A page doesn't need a full brand connector installed just to show one Fruitful-sourced fact. The Fruitful Brand widget renders read-only data through the same client, cache, and schema validator — and disappears cleanly when Elementor, the API, or the brand isn't there.

  • Every field passes through a schema validator first — no raw API field can leak
  • Degrades to an editor-only placeholder, never a broken block on a live page
  • Registered only when Elementor is actually active — no hard dependency
Architecture

One outbound call. One shape.

The plugin makes exactly one kind of outbound call — to the Fruitful Core App. A brand connector that also needs a Worker, a payment gateway, or a delivery API talks to those itself, the same way Banimal's own Connector talks to its Cloudflare Worker — never through this plugin.

The Fruitful Core App is the only thing this plugin ever calls. It authenticates once, caches every response, and maps every field through the schema validator before anything downstream — a REST response or an Elementor widget — ever sees it.

Security

Narrow by default, not by discipline

The rules this plugin follows aren't a checklist someone has to remember to run — they're the only code path that exists.

✓

Credentials only in wp-config.phpFRUITFUL_API_BASE_URL and FRUITFUL_API_TOKEN are read from PHP constants only — never the options table, a request, or an Elementor control. There's no settings form that could accept them.

✓

No secret reaches the browserThe admin status page's connection test runs server-side over a nonce-protected AJAX call and returns only success/failure and a status code — never a response body or a credential.

✓

Every response is mapped, not passed throughclass-schema-validator.php names exactly which fields become public before a REST response or a widget ever renders — an internal field the API happens to return can't leak by accident.

✓

Inert without configuration or without ElementorThe plugin activates safely with no PHP errors when the API isn't configured yet, and the widget registers only when Elementor is actually active — no dormant code path waiting to misfire.

Install

Four steps, no guesswork

  1. Add the API config.wp-config.php: FRUITFUL_API_BASE_URL and FRUITFUL_API_TOKEN.
  2. Activate the plugin.WP Admin → Plugins → Fruitful WordPress Core.
  3. Confirm the connection.Fruitful Core → "Test Connection" — hits the real API live, no cached fakes.
  4. Add the widget.Elementor editor → search "Fruitful Brand" → set a Brand ID.
